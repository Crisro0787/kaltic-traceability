# Google Apps Script Services

Kaltic uses Google Apps Script as a lightweight supporting service for selected processing tasks in the public MVP.

These services are called by the Joget application through HTTP requests. They do not define the full traceability architecture and do not represent every pilot workflow.

## Current public service

### Field registration

File:

[`field-registration.gs`](field-registration.gs)

This service supports the agricultural field / plot registration workflow.

It performs operations including:

- receiving field GeoJSON generated by the Kaltic interface;
- deterministic canonicalization;
- SHA-256 hashing;
- field-area calculation;
- sequential field identifier generation;
- satellite-image generation;
- IPFS upload through Pinata;
- returning processed values to Joget.

The resulting information can then be used by the Joget workflow when creating the field record and linking it to Cardano Preprod evidence.

### Required configuration

The service expects credentials to be provided securely through Google Apps Script Properties, including values such as:

```text
GOOGLE_MAPS_API_KEY
PINATA_JWT
```

Credentials, deployment IDs and private endpoints are intentionally excluded from this repository.

## Legacy harvesting service

An earlier harvesting service developed before the final September pilot architecture is retained under:

[`legacy/harvesting.gs`](legacy/harvesting.gs)

That script used an earlier record model with fields such as quantity, unit of measure and harvest start/end dates.

It is preserved for project-history transparency, but it is **not the final pilot workflow**.

During the final M3 validation, Kaltic evolved to a cut-based operational model:

```text
Producer / field / crop
          |
          v
         Cuts
   (operational records)
          |
    +-----+------+------+
    |            |      |
    v            v      v
 Delivery   Transformation   Aggregation
```

Cuts themselves did not independently require Cardano transactions. The selected downstream pilot-specific events generated the blockchain evidence documented elsewhere in the repository.

- [`../../docs/pilot-workflows.md`](../../docs/pilot-workflows.md)

## Canonicalization and hashing

Public supporting services use deterministic structured-data processing before hashing where applicable.

Conceptually:

```text
Operational data
      |
      v
Structured record
      |
      v
Deterministic canonicalization
      |
      v
SHA-256 digest
      |
      v
Application / evidence workflow
```

This supports later comparison between off-chain records and associated cryptographic evidence.

## Security

Secrets must never be hardcoded in the public scripts.

The repository intentionally excludes:

- Google Maps API keys;
- Pinata JWTs;
- private Google Apps Script deployment URLs;
- user or pilot data;
- wallet credentials;
- signing keys;
- Blockfrost credentials.

Sensitive configuration should be supplied through secure environment or script-property mechanisms.

## Scope note

These files document supporting code used during the Catalyst F11 prototype period. They should be read together with the final architecture documentation rather than as a complete standalone implementation of every validated pilot process.
